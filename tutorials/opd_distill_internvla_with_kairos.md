# Distill InternVLA-A1.5 with Kairos OPD

References: [VLA-OPD](https://arxiv.org/abs/2603.26666) and the
[official Kairos repository](https://github.com/kairos-agi/kairos).

This integration uses Kairos as a separate HTTP teacher and InternVLA-A1.5 as
the student. It is designed for student-generated rollout datasets: each state
in the dataset must have been visited by the current student policy. Relabeling
an expert/offline dataset is ordinary knowledge distillation, not on-policy
distillation.

Kairos returns continuous action samples rather than token logits. The training
loss therefore estimates a diagonal teacher distribution from multiple seeded
Kairos samples and minimizes a continuous Gaussian `KL(student || teacher)`.
The student's mean is reconstructed directly from its flow-matching velocity.

## 1. Run the Kairos service

Install Kairos in its own environment, using the official benchmark guide and
the checkpoint/config matching the rollout embodiment. From the Kairos checkout:

```bash
export WAM_CFG_PATH=/path/to/robotwin_wam_infer_config.py
python -m uvicorn benchmarks.common.wam_service.server:app \
  --host 127.0.0.1 --port 8006
```

The Kairos runtime and InternVLA runtime intentionally remain separate. Verify
the service before training:

```bash
curl http://127.0.0.1:8006/health
```

Keep the Kairos benchmark `dataset_stats.json` next to the matching checkpoint.
Its state/action dimensions and normalization must match the rollout robot.

## 2. Prepare an on-policy dataset

Collect a LeRobot dataset by executing the current InternVLA-A1.5 checkpoint.
The dataset must contain raw state, task text, and the camera keys declared by
its dataset schema. Run a new collection/distillation round after updating the
student if strict on-policy freshness is required.

`--dataset.opd_rollout_dataset=true` is an explicit assertion about provenance;
the loader cannot infer whether a dataset was actually generated by the student.

## 3. Start distillation

In the InternVLA environment:

```bash
KAIROS_ENDPOINT=http://127.0.0.1:8006 \
TEACHER_SAMPLES=4 \
bash launch/internvla_a15_opd_kairos.sh \
  owner/student-rollouts \
  /path/to/kairos/benchmarks/robotwin/robotwin_dataset_stats.json \
  abs
```

Important options:

- `opd.teacher_samples`: seeded Kairos samples used to estimate uncertainty.
- `opd.teacher_std_min/max`: floors variance and masks overly uncertain teacher dimensions.
- `opd.student_std`: fixed student proxy standard deviation used by reverse KL.
- `opd.sft_loss_weight`: mixes the original flow-matching target with OPD.
- `opd.action_horizon`: override only when the Kairos checkpoint horizon differs.
- `opd.batch_requests=false`: use if a custom Kairos engine does not support batches.

The official service serializes requests with pickle. Non-local teacher URLs are
rejected by default; only set `opd.allow_remote_pickle=true` on a trusted network.
